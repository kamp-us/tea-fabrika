# Supervision follows OTP, with one tree per program

Each program is its own OTP-style application with its own supervisor and restart count, so one program's crash loop never stops another. `Program.supervise` takes its restart policy inline, as an Effect `Schedule`, in the shape of `Stream.retry(stream, schedule)`: `Program.supervise(checklist, { restart })`, or piped. When the Schedule ends, the program stops and waits for a person to restart it, never a timer: the old timer-retry restarted a name that always throws about 86,000 times a day. A stop fails the stream with the defect's cause, so a parent supervisor hears it, which is OTP's escalation. The `Supervisor` service only records each restart and stop; it no longer decides them. Isolation also has hard walls, not code alone: write and storage quotas per program and a CPU limit per isolate.
